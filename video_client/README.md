# video_client

前端：Vue 3 + 原生 HTML/CSS/JS，**没有构建步骤**，不需要 npm install。

## 跑起来

前端由 `video_server` 直接发，所以只要把后端跑起来：

```bash
docker compose up -d --build        # 在仓库根目录
# 浏览器打开 http://127.0.0.1:9000
```

> 摄像头只在 `https` 或 `localhost` 下才可用。`http://127.0.0.1:9000` 算安全上下文，
> 所以没问题；但 `file://` 双击打开大概率拿不到摄像头（接口能通，页面会提示你直接进房间）。

## 文件

```
index.html          页面骨架 + 四个视图的模板 + 图标 sprite
app.css             全部样式（设计变量在最上面）
app.js              全部逻辑：视图状态、接口调用、登录状态、摄像头/麦克风
tools/vendor.mjs    把 Vue 和 Tabler 图标拉到本地，并生成 sprite
vendor/             Vue 3 全局构建（完整版，带模板编译器）
```

`vendor/` 和 `index.html` 里那段 `<svg>` sprite 都由 `tools/vendor.mjs` 生成，
要升级版本或加图标就改那个文件里的常量再重跑（需要能上网）：

```bash
node tools/vendor.mjs
```

## 视图

`app.js` 里只有一个 `view` 变量，走 `booting -> auth -> lobby -> room`：

1. **booting** 页面加载时先试着恢复登录状态。这一步单独有个占位，不然会先闪一下登录页。
2. **auth** 登录 / 注册。左边是品牌，右边是表单；下面那行是真实的 `GET /api/health` 结果，
   它同时也说明数据库通不通。
3. **lobby** 进房间前。左边是自己摄像头的真实预览，右边两个入口：「加入会议」填别人的房间号，
   「创建会议」开一个新会议（系统分配 9 位数字房间号）。
4. **room** 会议中。房间号、在线人数、时长，画面网格，麦克风 / 摄像头 / 离开。

## 登录状态存在哪（这部分是重点）

浏览器里没有 SQLite 的位置：这是浏览器页面，不是 Node 程序，要跑 SQLite 得上
wa-sqlite / sql.js 那种 WASM 版本再配一层持久化适配，为了存两个字符串引入几百 KB
的 WASM 不划算。浏览器原生的持久化 —— `localStorage` / `sessionStorage` / Cookie ——
就是这件事的正确工具。所以：

| 存的东西 | 存在哪 | 为什么 |
|---|---|---|
| 短会话令牌（服务端 12 小时） | `sessionStorage` | 每个标签页一份；但一个账号同时只有一个有效会话（见下面"挤下线"） |
| 长期令牌（服务端 30 天） | `localStorage` | 勾了"保持登录"才有，关掉浏览器明天回来还认 |
| 上次的用户名 | `localStorage` | 这就是"记住账号"，占位符那栏不用重打 |

**不存密码。** 也不该存。存了就等于：任何能碰到这台电脑的人、任何一次 XSS，
都拿到一个多半在别处也在用的明文密码。存令牌能得到同样的体验，而令牌是能过期、
能吊销、能被服务端主动作废的。所以界面上是「保持登录 30 天」，服务端发的是长期令牌。
（`smoke` 和浏览器测试里都有一条断言：密码不出现在 `localStorage`、`sessionStorage`
和 cookie 里的任何位置。）

一个账号同时只有一个有效会话：换设备登录、或用长期令牌换新会话，都会把上一个挤下线
（服务端会把这账号的其它令牌清掉，并立刻清掉它的会话校验缓存）。
所以**同一个浏览器开第二个标签页会顶掉第一个标签页**；本地"自己跟自己测多人"要
**再注册一个账号**（首页那两个入口是「加入会议」/「创建会议」，注册第二个账号即可）。
大厅每 2 秒验一次会话（心跳，和房间轮询一样快），被顶掉的那一屏会自己回到登录页。

流程：

- 打开页面 → `booting`：有短会话就验一下；没有就拿长期令牌 `POST /api/session/resume`
  换一个新的；两个都没有才去登录页。
- 用着用着短会话过期（401）→ 自动用长期令牌换一次再重试，不会把人踢出去。
- 退出登录 → 服务端把短会话和长期令牌都删掉，本地清干净，但**用户名留着**。

## 能做到什么 / 做不到什么

真的能用：

- 注册、登录、退出；重名、密码错、会话过期都有明确提示
- 勾"保持登录"后关掉浏览器再回来还是登录状态；开新标签页自动进大厅
- **两个人、三个人真的能互相看见和听见**（WebRTC mesh，两两直连）
- 本地摄像头预览、麦克风开关、摄像头开关（静音只改 `track.enabled`，不停 track，
  所以再打开不需要重新授权，也不会触发重新协商）
- 房间进出、多人在线名单、可复制的邀请链接（`#房间号`，对方打开会自动填好）
- 摄像头被拒绝 / 被占用时给出能照着做的提示，且不带画面也能进房间
  （这时会建只收不发的连接，仍然能看到别人）
- 连接不稳会自己恢复：切网 / 瞬断自动 ICE restart；15 秒建不起来的对端会被看门狗重建重试（最多 3 次）；
  页面从后台切回前台立刻补一拍心跳
- 外接摄像头 / 麦克风热插拔会自动重取并换轨（尽力而为，见 `app.js` 的 `recoverMedia`）
- 屏幕共享：会议室里点「共享屏幕」，对端画面无缝切过去（`replaceTrack`，不触发重新协商）；
  点「停止共享」或浏览器共享条里的停止按钮都能切回摄像头

还不能：

- **4-6 人以上**。mesh 下每个人要给其他每个人发一路，上行是 (N-1) 倍，房间上限就是 6。
  要开更多人得换 SFU。
- 屏幕共享、聊天、举手、录制、虚拟背景、字幕都没有。
- 看不到"对方已静音"（需要额外发一条状态信令）。
- 跨网络时需要 TURN。默认只有一个公共 STUN，局域网和本机不用管；
  对称 NAT 或企业网下会有连不上的情况，那就得自己起 coturn 并把
  `ICE_SERVERS` 指过去。

## 媒体是怎么接起来的

```
浏览器 A ──POST /api/rooms/signal──► 服务端收件箱 ──GET /api/rooms/state──► 浏览器 B
   │                                                                          │
   └──────────────── SRTP / UDP，两两直连，不经过服务器 ──────────────────────┘
```

- 服务器**只搬信令**，而且不认识内容：`payload` 是原样转发的 JSON 片段。
  加屏幕共享、改编解码、以后换 SFU，后端都不用动。
- 每个对端一条 `RTCPeerConnection`，放在组件外面一个普通 `Map` 里。
  **不能放进 Vue 的响应式数据** —— `RTCPeerConnection` / `MediaStream` 被 Proxy 包一层会出怪问题。
  界面要用的状态另外用 `peerState` / `peerHasVideo` 同步过去。
- 冲突处理用的是 W3C 的 **perfect negotiation**（两边可能同时发 offer，由"礼貌"的一方回滚），
  不是自己发明的简化版。以后加屏幕共享要重新协商时，同一套逻辑照用。
- 轮询间隔是自适应的：还有对端没连上就 400ms，都连上了退回 2 秒。
- 信令消息**一条一条 `await` 处理**。并发处理的话，紧跟 offer 后面的 ICE candidate
  会在 `setRemoteDescription` 还没完成时撞进 `addIceCandidate`，直接抛 InvalidStateError。
  另外 remote description 还没到的 candidate 会先攒起来，等描述到了再补。
- 浏览器会拦带声音的自动播放。正常点"加入会议"那一下就够了，被拦时会显示一条提示按钮，
  不然现象是"看得见人听不见声"，很容易误以为是 WebRTC 坏了。

调试：控制台里有 `window.tongpin`，能看到每条连接的状态和统计。

```js
[...tongpin.calls].map(([pid, c]) => [pid, c.pc.connectionState])
await (await [...tongpin.calls][0][1].pc.getStats()).forEach(r => console.log(r.type, r.kind, r.bytesReceived))
```

## 设计上的几个决定

**浅色企业工具风**，排版按国内主流会议软件（腾讯会议 / 钉钉）的习惯来：
浅灰底 `#F2F3F5` + 白卡片 + 1px 细边框分层（不靠阴影）、较方的圆角、偏紧的间距。
上一版是暗色 + 大标语 + 不对称分栏，那是落地页的语言；这是个工具，登录页就该长得像个登录页。

- **配色参考腾讯 TDesign 的默认 token：主色 `#0052D9`**，红色 `#D92D20` 只用于"离开会议"
  和已静音这类状态。**没有用 TDesign 的官方组件包** —— 这个项目的前提是没有构建步骤，
  引不了 npm 包，所以 CSS 全是手写的，不冒充在用 TDesign。
- **有两处故意没照抄 token，因为过不了 WCAG AA**：三级文字用 `#6B7280` 而不是
  TDesign 的 `#86909C`（后者在白底上只有 3.24:1，而它正好用在占位符和提示文字上）；
  危险色用 `#D92D20` 而不是 `#F53F3F`（后者配白字只有 3.71:1）。两处都记在 `app.css` 顶部。
- **视频块保持深色**。视频本来就该在深底上看，而且这样一眼能分清"内容区"和"界面区"。
- **圆角只有四档**：2 / 4 / 6 / 8px + 全圆。中文企业工具比西式 SaaS 更"方"。
- **动效只做反馈**：按钮按下、视图切换、骨架屏呼吸，强度压得很低，
  全部包在 `prefers-reduced-motion: no-preference` 里。
- **加载态用骨架屏**（和登录卡片同形状），不用转圈。
- **图标来自 Tabler Icons**（MIT），没有手画 SVG 路径；复选框和滚动条都用原生能力
  （`accent-color`、`scrollbar-color`），不自己造控件。
- 文案都写实话：媒体没接上就写媒体没接上，数据库不通就直说数据库不通。

> 改 `index.html` 之后记得跑一次 `node tools/vendor.mjs` —— 图标 sprite 就嵌在
> `index.html` 里，重写这个文件会把它清掉（`docker compose run --rm test` 里有一条断言能发现这件事）。

## 已知缺口

- 4-6 人以上要用 SFU，不是 mesh。
- 在线状态和信令都是轮询，最多 0.4-2 秒延迟；人走掉最多约 30 秒后才消失（服务端 30 秒没心跳才判离线，
  前端还会再等两拍才断开连接 —— 宁可多等一会儿，也不在弱网下误拆健康连接）。
- 手机端锁屏 / 切后台会被系统挂起 JS，超过心跳阈值别人会把你判成掉线（宽限期救不了锁屏）；
  进房时会尝试申请屏幕常亮（Screen Wake Lock，不支持的浏览器静默跳过），手动锁屏仍会掉线。
- 信令是尽力投递，服务端重启会丢消息；卡住的协商会被看门狗自动重建重试，连着重试 3 次还不行才需要退了重进。
- 没有录制（屏幕共享 + 房间文字聊天 + 举手 / 表情已支持）。
- 长期令牌放在 `localStorage`，理论上能被 XSS 偷走（HttpOnly Cookie 更安全）。
  这个页面不渲染任何用户输入的 HTML，XSS 面很小，而且令牌可吊销、换设备登录会把旧的
  挤下线 —— 权衡下来选了前者。
- 退出登录会把长期令牌一起吊销，所以另一个标签页的"保持登录"也会一起失效。
- 用户名的显示没有做防冒名（同名的两个人看起来一样），要做得在服务端加唯一约束或加后缀。
- 主持人 = 建房的人；主持人离开且房里还有人时，角色交接给剩下的第一个人。被主持人移出的
  人只是被清出房间（登录还在），回大厅后还能重新进。
