# 同频 · 视频会议

![CI](https://github.com/liujinpeng597/video_conference/actions/workflows/ci.yml/badge.svg)

自托管的视频会议：浏览器之间 WebRTC 直连，后端只做账号、房间和信令。

```bash
cp .env.example .env    # 填上 POSTGRES_PASSWORD (本地开发随便填)
docker compose up -d --build
# 浏览器打开 http://127.0.0.1:9000
# 想试两个人开会: 再开一个标签页注册另一个账号, 填同一个房间号
```

## 部署结构

一条 `docker compose up` 起来的是完整的一套：

```
                         浏览器
                            │
                    ┌───────▼───────┐
                    │     nginx     │  静态文件 + 反向代理 (生产上加 TLS / WAF)
                    └───────┬───────┘
              ┌─────────────┼─────────────┐
        ┌─────▼────┐  ┌─────▼────┐  ┌─────▼────┐
        │  app 1   │  │  app 2   │  │  app 3   │   三个后端进程, 各自无状态
        └──┬────┬──┘  └──┬────┬──┘  └──┬────┬──┘
           │    └────────┼────┼────────┘    │
           │        ┌────▼────▼────┐        │
           └───────►│    Redis     │◄───────┘   房间在线状态 + 信令收件箱
                    └──────────────┘
                    ┌──────────────┐
          账号/会话 │  PostgreSQL  │
                    └──────────────┘
```

这些容器是用**同一台机器上的多个进程**模拟多台服务器。每个 app 容器是独立进程、
独立内存，互相之间只有 Redis 和 PostgreSQL 两条线。搬到真机器上只要改连接串。

反复请求 `/api/health`，返回里的 `instance` 会在三台之间变，这就是负载均衡在生效。

## 各目录

| 目录 | 是什么 |
|---|---|
| `video_server/` | C++17 后端：epoll + 线程池 + HTTP/1.1 + WebRTC 信令。**[README](video_server/README.md)** |
| `video_client/` | Vue 3 前端，没有构建步骤。**[README](video_client/README.md)** |
| `nginx/` | 入口层（静态 + 反代 + 限流；HTTPS 与证书说明见其 README） |
| `coturn/` | TURN 中继镜像的构建（用 Ubuntu 包，理由见 Dockerfile） |
| `docker-compose.yml` | 整套编排（含 coturn 中继） |
| `docker-compose.prod.yml` | 生产覆盖：HTTPS + 80/443 入口 |
| `.env` | 本机配置：数据库口令 / TURN 密钥 + 镜像站（`.env.example` 是模板） |
| `ops/` | 运维脚本：备份 / 恢复、降级演练、证书、TLS 冒烟、浏览器 E2E、事件流冒烟（`loadtest/` 是 k6 压测） |
| `DEPLOY.md` | 上线手册：VPS 加固 / 证书 / 备份 cron / 升级回滚 |

## 现在能做什么

**真的能用：**

- 注册、登录、退出、保持登录（两层令牌，可吊销）
- **2-6 人真的能互相看见和听见**（WebRTC mesh，浏览器两两直连）
- 麦克风 / 摄像头开关、屏幕上的本地预览、邀请链接
- 弱网自愈：切网自动 ICE 重启，协商卡住的连接由看门狗自动重建重试
- 三个后端实例 + nginx 轮询，杀掉一台不影响服务
- 限流三层：nginx 按 IP + 后端按账号失败锁定 + 后端按令牌（防爆破、防单账号被脚本刷）
- 屏幕共享（`replaceTrack` 无缝切换，对端不重新协商）
- 房间内文字聊天（复用状态轮询带回，不额外发请求；消息在 Redis 里留最近 50 条）
- 举手（进房间状态，别人能看见）与表情反应（走信令广播的瞬时效果）
- 静音状态同步（谁静音了房间里看得见）
- 通话质量指示（每格右下角显示收码率 / 丢包率，颜色分好 / 一般 / 差，悬浮看抖动与往返）
- 虚拟背景（**简易人像模式**：中心人像清晰、四周模糊或纯色；摄像头→canvas→`captureStream`→
  `replaceTrack` 换出向视频轨，对端看到的就是处理后的画面。没做 AI 抠像，理由见 `video_client/README.md`）
- 主持人（建房的人）：全体静音、把某个成员移出会议（服务端校验权限）
- 会议锁定（主持人锁上后新人进不来，已在会的人不受影响）与**会议密码**（建房时可选：勾上就是
  加密房间，房间号 + 密码才能进；不勾是普通房间。密码存房间 hash 的 `@pass` 字段，Argon2id
  哈希，跟着房间 TTL 一起过期；锁和密码互不影响，加密房间照样能锁）
- 修改密码（校验旧密码；改完把其它令牌全吊销——别的设备自动下线）
- 视图：点某一格放大成"演示者视图"（再点/按 Esc 回宫格）、全屏；快捷键 `m` 静音 / `v` 关摄像头 / `f` 全屏
- 会议历史（进/离房时写 `room_visits` 表，大厅列出最近进过的房间 + 时长，一键把房间号填回输入框）
- 三个界面：会议首页（加入会议 / 创建会议各弹一个小窗口，两个窗口里都带**整套设备面板**：
  本地预览 + 静音 / 关摄像头 + 选摄像头 / 麦克风 + 试麦电平条——入会/建房之前先把设备调好；
  创建窗口里还有"要不要设会议密码"。首页本身就是这两个入口 + 最近会议）/ 个人中心（头像、
  昵称、改密码、退出登录）/ 会议中
- 昵称与头像（房间里显示昵称；头像浏览器里压成 128×128 再上传，其他人按 pid 取，不暴露登录名）
- 会中体验：成员面板（名单 + 主持人静音某人 / 移出 + 自己改名）、**布局切换**（宫格 / 我最大 /
  主持人最大，点某一格也能放大）、说话绿圈、共享中角标、进 / 出与举手提示音、离开前确认
- 能选摄像头 / 麦克风（记住选择）并有试麦电平条 —— 面板在"加入会议 / 创建会议"两个弹窗里

**还不能：**

- **4-6 人以上**：mesh 下每个人要给其他每个人发一路，上行是 (N-1) 倍。要更多人得换 SFU。
- 录制（屏幕共享 + 房间文字聊天 + 举手 / 表情 / 静音同步 / 虚拟背景已支持）
- 跨网络通话需要一台有公网地址的 TURN：compose 已内置 coturn，部署时把 `TURN_URL` 指过去即可；本机 / 局域网用不到
- TLS：开发默认明文 HTTP；`docker-compose.prod.yml` 一键开 HTTPS（证书怎么来见 `nginx/README.md`）

详细缺口在两个子目录的 README 里都列了。

## 跑测试

```bash
docker compose run --build --rm test
```

覆盖后端全链路（含两个独立进程共享 Redis 的互通测试、50 条并发信令的顺序断言）。
浏览器侧的音视频通路已脚本化：`docker compose up -d --build` 后跑 `node ops/e2e-media.mjs`
（CI 里自动跑）——三个无头标签页进同一房间，断言对端画面解码出帧、双向 RTP 字节数都大于 0。

可观测性（可选）：`docker compose --profile monitoring up -d` —— Prometheus 在
`127.0.0.1:9090`、Grafana 在 `127.0.0.1:3001`（预置「同频 · 总览」面板与告警规则）。
告警闭环 = Prometheus -> Alertmanager -> 通知渠道（本机默认是 `alert-sink`，收到就打印），
演练 `bash ops/alert-drill.sh`（CI 里也跑）。部署 / 升级 / 回滚见 `DEPLOY.md` 和 `ops/README.md`。
